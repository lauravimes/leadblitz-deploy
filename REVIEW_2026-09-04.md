# LeadBlitz v2 — Full Review (4 Sep 2026)

Scope: `~/leadblitz-v2` (leadblitz.co). Method: four parallel code reviews (search/scoring, outreach, platform/security, frontend/design) plus a live run of the app against a scratch Postgres with a real account: register → search → score → reports → email/SMS preview → CSV → credits. Findings marked **[verified live]** were reproduced on the running app; the rest were verified by reading code.

Bottom line: the product idea and the core loop work (search, score, PDF report are genuinely good). The codebase has three classes of problem: (1) production is on a broken deploy path with unpinned dependencies, (2) money/credit handling has holes in both directions, (3) the frontend has no error surface so failures look like "nothing happened". The design should be **kept and refined, not overhauled**.

## 2. Security

| # | Sev | Finding | Where | Fix |
|---|---|---|---|---|
| S1 | **Critical** | **Unauthenticated SSRF via the public `/score` tool** (and via `lead.website` in enrichment). Only check is `"." in url`; redirects followed; no private-IP guard; fetched content goes to GPT and the observations are reflected back. **[verified live: `http://127.0.0.1:8791/login` scored 53/100 and the cached evidence captured an email address from the internal page]** | `services/site_fetcher.py:47`; `routers/public_score.py:67-71`; `services/email_enrichment.py:62-69` | Resolve host, reject loopback/RFC1918/link-local/IPv6 equivalents on every hop; http(s) only; 2 MB cap; `text/html` only |
| S2 | High | **`request.client.host` is Render's proxy IP** — uvicorn is started without `--forwarded-allow-ips`. ## 4. Frontend & design

**Verdict: keep and refine. Do not overhaul.** The system is coherent: 15 px system font, near-monochrome palette with semantic green/amber/red, 6 px radius, 1 px borders, one breakpoint. Mobile layouts hold up (checked live at 375 px). Landing, blog and app share tokens. A redesign would cost weeks and carry every structural problem below straight into the new look.

What actually needs fixing, in order of leverage:

1. **No error surface at all.** htmx 2 doesn't swap 4xx/5xx and there is no `htmx:responseError`/`htmx:sendError` listener anywhere. Every 403/404/422/500 and every network drop looks like a dead button. Add one global toast in `base.html`, style `.btn.htmx-request`, render `status.error` in the progress partials, stop using `hx-swap="none"` on forms that can fail.
2. **401 handler returns a 302 to HTMX requests** → htmx follows it and **swaps the login page into `#results` / `#nav-credits` / `#stats-area`**. Return `HX-Redirect: /login` when `HX-Request` is present (`app/__init__.py:23-25`).
3. **Credit cost is invisible before every charging action** (Search 1, Score 1, Score-all 1/lead, Hunter 2, AI-write 1). Only SMS shows a cost, and it's wrong. Put "· 1 cr" on the controls; emit `HX-Trigger: creditsChanged` from charging endpoints and have `#nav-credits` listen.
4. **720 px container is too narrow for `/leads`, `/dashboard`, `/admin`.** Meta chips wrap 2–3 lines per lead; header buttons and filter bar wrap. Add `.container-wide` (~1100 px) for data pages and turn `lead_card.html` into a fixed-column row (select · name+address · email · phone · score · stage · actions). Keep 720 for auth/settings/compose.
5. **Inline styles everywhere** (hundreds of `style=""`, non-token colours, three hard-coded two-column grids that don't collapse on phones: `email.html:187`, `lead_detail.html:54`, `settings.html:178`). Replace with ~10 utility classes. Delete dead CSS (`.tab-panel`, `.package-*`, `.compose-grid`, `.preview-card`, `.sms-preview`).
6. **Onboarding doesn't exist.** `User.completed_tutorial` is never read or written. New user lands on an empty Search page; after results nothing says "score → report → email"; Reports only appear on the lead detail page *after* scoring; dashboard "Send emails" quick action drops them on a form asking for comma-separated UUIDs. Add a 3-step first-run checklist on the dashboard and put Report/Email actions on the scored card.
7. **Accessibility basics**: unlabeled filter selects and checkboxes, no `aria-expanded` on the three toggles, `outline:none` on inputs with only a border-colour focus indicator, `.score-high` contrast ~4:1 at 13 px.
8. **Self-host htmx** (`unpkg`, no integrity hash; every authenticated page is dead if unpkg is down) and make the app nav sticky like the landing nav; add Campaigns and Import to the Tools menu.

Other wiring bugs: `search.html:29` interpolates user input into `hx-vals` JSON without `tojson` (a `"` in a saved search breaks the click silently); AI-write handler reports "Done" on error responses (`email.html:148-161`); lead-detail header/Reports card don't update after scoring until reload.

**Landing-page claims vs reality:** "12+ dimensions" → 11; "branded with your agency name" → never wired; "Cancel anytime" → there is no subscription; "CRM pipeline" → a 4-value select and a notes box; "200 free credits" → conditional, with no message when withheld. Pricing matches `CREDIT_PACKAGES`.

## 5. Architecture notes

- **Five in-memory dicts hold user-facing state** (`_bulk_selections`, `_batch_status`, `_send_status`, `_enrich_batch_status`, `_rate_limits`). They work today only because there is one uvicorn worker, and they vanish on every deploy and every Render free-tier spin-down. The CSV import is the one background feature that keeps state in the DB — do the same for the others (a `jobs` table is enough), and run long work from a scheduler, not `time.sleep` in a daemon thread.
- **DB connections are held across network calls** in scoring (`get_cached_score` opens a transaction that stays open through up to 4 page fetches × retries plus an OpenAI call with no client timeout). 15 concurrent Score clicks exhaust `pool_size=5, max_overflow=10`.
- **Dead code to delete**: `services/credit_drip.py` (never imported), `CreditState`/`UserSubscription` (never written), `deps.require_admin` (re-implemented in admin.py), `send_single_email`, `client_report_json`, `internal_report`, `email_report`, `extract_phone_from_website`, `framework_detector.should_use_rendering`, `stripe_client.CREDIT_COSTS`, `EmailSignature.logo_url/disclaimer/custom_signature/use_custom`, the Gmail/Outlook OAuth routes if you don't finish them.
- **No tests directory.** Auth, credits, webhook and scoring have zero automated coverage. The Stripe regression (M1) is exactly the kind of thing one webhook test catches.
- The `fastapi<0.112` pin is not required by anything in the code (old-style `TemplateResponse` still works with a deprecation warning); the real need is a lockfile.
